# 圖片壓縮工具

批次壓縮 PNG / JPG / WebP，提供**無損**與**有損**兩種模式。

## 啟動

- **給其他電腦用**：把 `dist\CompressPicture-<版本>-win64.zip` 交給對方，「全部解壓縮」後雙擊 `CompressPicture.exe`。
  不需要安裝 Python 或任何套件；zip 裡附 `README.txt`（給使用者的說明）與 `selftest.bat`（雙擊做自我檢查）。
- **從原始碼執行**（開發用，需要 Python 3.12）：雙擊 `run.bat`（第一次會自動建立 `.venv` 並安裝套件）。

### 目標電腦需求

- Windows 10（1809 以後）或 Windows 11，64 位元（PySide6 的最低需求）。
- CPU 需支援 SSE4.2（約 2009–2011 年以後的 Intel／AMD；來自 numpy 宣告的最低指令集）。
- 不需要系統管理員權限、不需要 Python、不需要 Visual C++ 可轉散發套件（都已包在 `_internal` 裡）。
- 沒有數位簽章：第一次執行可能出現 SmartScreen「Windows 已保護您的電腦」，按「其他資訊 → 仍要執行」。
  若公司防毒誤判，需請 IT 加入白名單或替 exe 簽章。

### 已驗證的情境（1.1.0）

- 用 Windows 內建解壓縮（與檔案總管「解壓縮全部」相同引擎）解到含中文與空格的路徑。
- PATH 只留 Windows 系統資料夾、清除所有 Python 相關環境變數後執行：所有 DLL 都從套件內載入
  （Python、VC++ runtime 皆來自 `_internal`），自我檢查（6 種壓縮 + 介面）全部通過。
- 在設定了 `NoDefaultCurrentDirectoryInExePath` 的環境雙擊 `selftest.bat` 也能正常執行。
- 尚未在實體的乾淨電腦或 Windows Sandbox 上測過（這台電腦沒有啟用 Sandbox）。

## 使用方式

1. 把圖片或資料夾拖進視窗（資料夾會包含子資料夾），或按「＋ 加入檔案／資料夾」。
2. 右邊選擇壓縮模式和輸出位置。
3. 按「開始壓縮」。完成後雙擊清單中的檔案，可以左右並排比較前後差異（滾輪縮放、按住空白鍵在右側顯示原圖）。

清單右鍵：比較前後、在檔案總管中顯示、用目前設定重新壓縮、還原原始檔案、從清單移除。

**停止**：第一次按「停止」不會再開始新的檔案，等處理中的幾個做完就停（通常一兩秒）；
這時按鈕會變成「強制停止」，可以立刻中止處理中的檔案（這些檔案不會被修改）。
沒處理到的檔案維持「等待中」，再按「開始壓縮」會繼續。

## 兩種模式

| | 無損 | 有損 |
|---|---|---|
| PNG | oxipng 重新最佳化 | libimagequant 減少顏色（同 pngquant），再用 oxipng 最佳化 |
| JPEG | mozjpeg 重新編排霍夫曼編碼、轉漸進式 | 依品質重新編碼，再用 mozjpeg 最佳化 |
| WebP | 無損 WebP 重新編碼（有損 WebP 會略過） | 依品質重新編碼 |
| 畫質 | 完全不變（逐像素驗證） | 些微損失 |

## 安全保證

- **無損模式一定無損**：每個檔案壓縮後都會解碼並逐像素比對（包含透明像素底下的顏色、動畫 PNG 的每一格），不一致就保留原檔。
- **不會變大**：壓縮結果沒有比原檔小，就保留原檔。有損模式下若重新編碼反而變大（原圖品質本來就低），會改用無損最佳化，不會越壓越糊。
- **不會寫壞檔案**：一律先寫暫存檔再取代，中途停止或當機都不會留下半個檔案。
- **覆蓋原檔可以還原**：覆蓋前會先備份原檔，關閉程式前都能在清單右鍵「還原原始檔案」。再次壓縮時也會從原檔重新壓，不會壓到已經壓過的結果。
- **不會蓋掉別人的修改**：處理期間原檔被其他程式改過，就不寫入並提示重新壓縮；壓縮後被改過的檔案，還原前會先詢問；重新壓縮時以修改後的內容為新的原檔。
- **同一個檔案不會被處理兩次**：用檔案身分判斷（短檔名 `KAIHSU~1`、junction 等不同寫法都認得出來）。輸出檔不會蓋到清單中任何原始檔。
- **不會卡住**：子行程當掉（例如記憶體不足）時，只有造成問題的那張會被標為失敗，其他檔案會自動單獨重試；大圖依可用記憶體控制同時處理的數量。
- **輸出檔已存在會先詢問**；兩個來源對到同一個輸出檔名時會自動加上 (2)。
- 「移除中繼資料」只移除 EXIF、文字說明等；色彩描述檔（ICC）與照片旋轉方向一律保留。
- 動畫 PNG 在有損模式下只做無損最佳化；動畫 WebP、CMYK JPEG 的有損壓縮等容易出錯的情況會略過或改用無損，並在清單說明原因。

## 開發

```bat
.venv\Scripts\python -m pytest tests      :: 單元測試
build.bat                                 :: 打包 → 自我檢查 → 產生 dist\CompressPicture-<版本>-win64.zip
dist\CompressPicture\CompressPicture.exe --selftest report.json   :: 在其他電腦上檢查是否正常
```

改版時修改 `version.py` 的 `APP_VERSION`（會顯示在視窗標題、exe 檔案內容與 zip 檔名）。

| 檔案 | 內容 |
|---|---|
| `compressor.py` | 壓縮引擎與像素驗證（不依賴介面，在子行程執行） |
| `fileops.py` | 收集檔案、規劃輸出路徑、安全寫入、備份還原、「原檔是否被改過」的檢查 |
| `runner.py` | 子行程池、平行寫檔、停止／強制停止、當機隔離重試、記憶體預算排程（執行緒模型寫在檔案開頭） |
| `gui.py` | 主視窗 |
| `preview.py` | 比較前後視窗 |
| `main.py` | 進入點（含 `--selftest`） |
| `prune_build.py` | 移除打包結果中用不到的 Qt 元件 |
| `package.py` | 加入 `README.txt`、`selftest.bat` 並壓成 zip（檔名限定 ASCII，避免 Windows 10 內建解壓縮變亂碼） |
| `version.py`、`make_version.py` | 版本號與 exe 的版本資訊 |
| `README_dist.txt` | 隨 zip 附給使用者的說明（打包時改名為 `README.txt`） |
